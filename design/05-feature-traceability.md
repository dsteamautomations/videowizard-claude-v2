# VideoWizard v1 → v2 feature traceability

Date: 14 Oct 2026. Companion to [02-videowizard-v2-build-plan.md](02-videowizard-v2-build-plan.md). One row per operator-visible capability of `videowizard-beta` (v1), so the v2 rebuild cannot drop one silently. Dispositions are proposals; DROP (owner agreed 14 Oct 2026) rows need an owner decision (§4).

## 1. Method

Read-only pass over `videowizard-beta` on 14 Oct 2026. Enumerated: 115 backend route decorators in 23 modules (`backend/app`), 52 connector sub-commands (35 `add_parser` sites, some in loops) plus 27 other operator scripts, the 9 latest published procedures (57 named commands/actions), 16 frontend pages and 21 components, and the revision-action counts supplied from the live DB. Routes, connector commands, definition commands and pages for the same capability are collapsed into one row; evidence cites 1–3 representative items. Features whose work lives in job tables rather than revision actions (analysis, media uploads, references, video takes) are marked *indirect*.

Disposition vocabulary (plan §5): **next** = `GET /runs/{id}/next`; **output** = `POST /runs/{id}/output`; **chat acceptance** = explicit yes stored as `accepted_quote`; **jobs** = `POST /runs/{id}/jobs` with provider workers, cost informed not gated; **view/revise**; **409 options** = `NEEDS_USER_DECISION`; **files/sign** = signed upload + receipt. Slices per plan §9.
