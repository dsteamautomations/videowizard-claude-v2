## The change, rule by rule (short; the full text is Revathi's)

- **F7.** `State.gaze` = {target: landmark id or element id, head_turn: words with a degree, mouth: words}; required on a person's states in a video shot whose framing shows the face (any framing not "hands" / "from behind": the plan says `face_in_frame: bool` per shot, default true for a person). `check_prompt` refuses "as before", "facing each other", "sit as before", "the parents as before". The server composes the eye-line sentence into start_targets, end_targets and the motion text, plus the two constraints; one must line on the end picture: "each person's eyes are on the named target, head and mouth as written; no one looks at the lens". Plan warning (not refusal) when a shot's only change is a look: "prefer a profile, a back view or hands in close".
- **F8.** `Shot.fixed: [landmark ids]`, exactly three (or every landmark when the scene has fewer), required on video shots; none may be an element in `objects`; the server writes "The background is Image 1's background: a, b, c are in the same place, same size, same light." into the end prompt and the motion text; one must line on the end picture and the take: the three things unmoved.
- **F9.** A beat whose `action` or `done` has a placing verb (lay, set, put, fit, stack, join, fix, place) and whose subject's end `objects` or `props` name the placed thing: the server writes "<object> rests on <surface> with full contact; lined up with <neighbours>; <joint> of <n mm>; not tilted, not floating" from the element's visual facts and the material spec (F10); when no number exists the line carries no number (never a guess); one must line on the end picture.
- **F10.** `Element.material_spec` (unit size with units, `laid`, `joint`, `pattern`, each value a `Dimension` with source, status, tried; `not_this` from F12) for elements of kind material or any element the plan marks `repeating: true`; made with the drawing-spec machinery (sources in order, `measure`, table, one-click approval on the References step beside the sheet, correction box, rule 0's correction wait); `Element.size` folds into it. The server pastes the spec sentence into every prompt that shows the element (keyframe, isolated, sheet, drawing); `check_prompt` refuses "short", "long", "about n:1", "roughly", "standard", "typical" in a prompt that shows a material; one must line: the unit ratio on three units and the pattern across three courses. A drawing shot of a material with a spec uses it; it needs no `drawing_spec` of its own.
- **F11.** `element.golden` = reference id, set when the operator approves the picture the References step asks for right after the sheet and the spec (one paid picture per non-person element; a person's identity sheet is its golden picture). Parent rule: a picture of an element with a golden picture has it as Image 1; a derived parent (a keyframe or state made from another keyframe or state) is refused with the golden picture named; a picture with `not_yet_ok` or approved after a rejection with words cannot be golden; the footage-frame rule applies to the golden picture's making. Edit route: `region` (see question 3) required for an edit of a keyframe, the region at most a third of the frame, one change; the server composes the keep list (F8 fixed things, F4 inventory, F16 description, F5 tool line, F10 spec); after the model answers, the worker composites the parent's pixels back outside the region and measures that the outside is unchanged (the picture is refused when it is not). The page shows the golden picture per element and warns on a card whose parent is not it. Graphic states keep their chain and get the composite-back; a fix round's output is never a parent; drawings are outside editing.
- **F12.** `material_spec.not_this` (and `element.not_this` for other elements): built at the spec step from (1) the differences between untick ed web results plus "nothing fits" reasons and the approved sheet, (2) one model call "the common variants of X that differ from the spec" (Gemini 3.8 Flash, the check model), (3) every rejection of a picture of the element, appended as it happens; shown with the spec, approved by the same click; pasted into the constraints of every prompt of the element; `check_prompt` refuses such a prompt without the list; stored on record under `server/library/feedback/<element name>.yaml` so the next film starts with it. A shot that names an exception (`allows: [...]`) keeps that item out of its line.
- **F13.** `exact_text` entries become {text, place: landmark id or frame region, size_pct}; an entry with no place is refused; the prompt says "Render exactly this text, letter for letter, nothing else: '…'" and "no other letters, numbers or logos anywhere"; `check_prompt` refuses quoted words in a prompt that are not an exact-text entry; the must lines "reads exactly", "where the entry says, at that size" and "no other lettering" run on every picture with exact text. Old answers with plain strings still load (place empty; refused only on a new picture).
- **F14.** The plan check derives the elements a video shot needs: every id in `holding` and `props` (already elements) and every technique verb in the beats (pointing, plastering, planing, rendering, curing, …: a list in the code, extendable) must be an element of kind `object` or the new kind `technique`; a plan missing one is refused with the ids to add; they join the single round like any element (`round_start` accepts kind technique).
- **F15.** When a shot's `claims` or `descriptors` carry a size word (small, large, less, fewer, thin, short, light, tall, heavy, …), the subject element must have a size value and the shot a `compare_to` element in frame; the plan check refuses otherwise; the server composes "<subject>, <value> <unit>, <comparison> the <element>" into the prompts; the "true sizes" line becomes a must on that picture.
- **F16.** `Element.description` for persons (fixed layer: build, age, skin, hair, posture, garment types and how worn), written at the References step and approved with the sheet; `Scene.outfit: {element_id: colours}` per scene, with `Scene.time_jump: str` (the script's words) when colours change from the scene before; the plan check refuses a scene showing a person without an outfit, and a colour change without a time jump; the server pastes the fixed layer plus the scene's colours into every prompt and the continuity line, and the garment negatives into F12's list; the check compares against both layers.
- **F17.** `Shot.groups: [{kind, count, mode: same|different, reason (same), items: [trait each] (different)}]` for every kind that appears more than once in frame; the plan check refuses a shot that names several of a kind (count > 1 in `objects`, or a group word in the layout) without a group entry, and a `different` group with fewer items than its count; the server writes the layout line ("no two alike" or "all alike"); two must lines; the look-alike pass gains a figure-level comparison for background people and animals across the pictures of one scene (question 7).
- **F18.** Place elements gain `signs_of_use: [{what, landmark_id}]`; the server picks two per shot (round robin, never the scene's previous pair) and writes them against their landmarks; the real-light line is composed once per run from the measured footage character and added to every keyframe and isolated prompt; a new must on place pictures ("the place looks occupied or in use"); the measured light line against the footage frames moves from should to must (question 8).
- **F19.** A spec may carry `illustrative: true` only when every unknown dimension has `tried` naming all four sources (the client's material, the footage frames, a standard or maker figure, an approved picture); the plan check refuses otherwise; the run's count of illustrative specs against all specs goes to status and the page, with a warning above one in four naming each; `DrawingSpec.view: cutaway|plan|side|elevation` with `view_reason`, a wall section defaulting to cutaway; the known sizes go on the drawing as F13 exact-text labels on their parts; the check: sizes on the parts or the illustrative label, never neither. Server-drawn drawings (E1–E5) are not in scope until the steady-takes note exists.
- **F21.** `generate_image` refuses more than four parents after the server adds the inherited sheets, names the extra ones, orders them (the picture edited or the scene parent; one identity sheet per person in frame; one material or look frame), and requires one job line per image in the prompt ("Image k is …: take …"), refusing a prompt that lacks one. The model's 16 stays the hard ceiling.

## Unstated but expected

- Old plans and sessions load; every new field defaults; the new refusals fire on video shots when a plan is submitted again; no preparation digest moves for a take already ready (new lines go into the packet context and are appended to prompts at queue time, as batch 1 does).
- Every new sentence is server-composed from plan data and appended under the writer's prompt when missing (`with_composed`), never retyped by the assistant; every new check line rides on the existing Gemini call.
- One flow, two front ends: the material spec, the golden picture, the description and the not-this list are approved on the page and through `vw visuals` alike.
- Costs stated to the operator: one golden picture per non-person element (about 4 INR each), one Gemini call per element for the not-this list (pennies).

## Edge cases and failure modes (the full list goes into each sub-set's tests)

- A scene with fewer than three landmarks (F8); a person framed from behind (F7); a place with no footage (F18's signs from references only); an element with no web results (F12's source 1 empty); the model's not-this call failing (the list is built from sources 1 and 3 and the spec step says so); a golden picture rejected later (the element has none until a new one is approved; new pictures of it are refused until then, rule 0 asks the operator); an edit whose region covers more than a third (refused with the size); the composite-back when the model returned a different size (resized to the parent before compositing; refused if the aspect differs); a time jump the script does not state (refused; the planner asks the operator once, rule 0); a group of one (no entry needed); exact text with a place the scene does not have (refused).

## As built: F11 (+F41) (27 Oct)

- `session.golden` maps an element to its golden picture. `status.golden_due` names each non-person, non-graphic element whose sheet (and material spec) is approved and that has no golden picture made or being made, with the `vw visuals image … --golden --parents <sheet>,<frame>` line the assistant runs at once (SK's answer 4).
