# design/86 — Pictures right the first time: the seven corrections from the VW-6 review

Status: requirements note, builder, 23 Oct 2026; SK: "I agree with all seven points. Start with the implementation." Source: `image-generation-review-2026-10-23.md` (11 of 24 keyframes right first time on VW-6; the causes C1–C5). Built for VW-7.

| | Correction | What changes | Where |
|---|---|---|---|
| K1 | **The pre-written pair.** A start keyframe may carry its end prompt and answer form (`end_prompt`, `end_answer`) at generation; the server stores them on the start as `pending_end`. When the start is approved (page or chat), the server queues the end image itself from the approved start with its references, no chat turn. The step says to write both prompts together and post both. | `generate_image`, `approve_reference`, `vw.py` (`image --file` rows gain `end_prompt`, `end_answer`; `--end-answer`), step 4 |
| K2 | **The check before the operator.** When an image job is retained, the worker checks the candidate: the code checks size, aspect and parent; Gemini Flash (the analysis stage's transport, JSON answer) reads the candidate, its parents and the answer form's checklist and answers pass or fail with one sentence per line, plus three fixed questions (readable text, a face matching a footage frame, anything not asked for). The result is stored on the reference as `check` and shown on its card line by line. On a must failing, the worker queues one fix round: an edit of the candidate with a single change taken from the failed line's pass condition (the library's fix-round form), marked `fix_of`; the fix is checked too; never more than one. The operator may approve a picture the check failed. A failed check or a transport error never blocks: the candidate stays a candidate with `check: {error}`. | new `image_check.py`, `visual_workers.finalize_image`, the page's cards |
| K3 | **The page says whose turn it is.** On the Takes step each video shot's card carries one state line: start generating (about 1 min; nothing to do; the page refreshes), checking (under 30 s), start ready (your turn), end generating, pair ready (your turn), take submitted (about 3 min; you may leave), take ready (your turn), or waiting for the assistant (no end prompt yet). The step's head counts: N want your decision · N being made · N wait for the assistant. | `visuals.html` |
| K4 | **Two candidates per start.** `image` accepts `variants: 2` for a keyframe start: two jobs with the same prompt and answer, names suffixed `-a` and `-b`; the operator approves one; the pending end goes with the approved one. The plugin: `--variants 2` and the row field. | `generate_image`, `vw.py` |
| K5 | **One change per edit.** `check_prompt` on an edit whose text has a "Change only:" section refuses when that section holds more than two sentences; the message says to make two edits. | `library.check_prompt` (edit flag), step 4 |
| K6 | **The end target written by the server.** The packet renders each subject's end state into one sentence: "<element> ends <relation> <landmark description>, facing <facing>, <pose>, holding <…>, <progress>." under `end_targets`; the end instruction says to carry them word for word. | `packet` |
| K7 | **The packet's context** (approved). `gap_words` (the gap's narration from the package's words for its passages), `treatment_picture` (the treatment entry's picture line and routes), `intended_visuals` for the gap, `neighbours` (the previous shot's subjects' end states and the next shot's start states inside the gap), `earlier_rejections` (the rejection words of rejected references of the shot's elements). | `packet` |
| K8 | **Client patterns as a texture reference.** The step: an object element with exact identity (a bond, a product, a uniform) has one isolated close reference, a footage frame or a generated `isolated` picture, approved and bound to every shot that shows it; the prompt names the geometry in nouns; the checklist demands the pattern only at medium and close shots. The packet lists such elements under `exact_patterns` with their bound references. | step 4, `packet` |
| K9 | **Count the rounds.** `feedback_yaml` opens with a summary: per kind, pictures right first time, pictures that needed rounds, and the average rounds per approved picture. | `feedback_yaml` |
| | Server 0.32.0, plugin 0.30.0. | |
